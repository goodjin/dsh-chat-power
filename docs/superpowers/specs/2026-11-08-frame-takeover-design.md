# 帧渲染接管（设计）

## 为什么接管

会话区的每一轮由宿主渲染成若干「节点行」：用户请求、思考（工作步骤）组、工具调用、
最终回答。宿主自己管这些内容的折叠与预览——思考在流式期间**只给一行摘要**，组头
自带折叠，工作步骤收起后决定留下哪些回复。

我们此前是在宿主的渲染结果上做文章（加属性、插自己的条、点它的展开控件），于是宿主
每改一条规则，我们就跟着打架：思考只有一行、框套框、思考跑到框外、文案漂在框外。
现在改成**帧的渲染由我们接管**：内容仍然用宿主自己的组件渲染（不重新实现 Markdown），
但**帧的外壳、内容编排、标题行、展开与裁切由我们决定**。

## 分工

| 部分 | 谁渲染 |
| --- | --- |
| 思考正文 | 我们从节点数据取 reasoning 原文 + 宿主 `MarkdownText` |
| 回答正文 | 宿主原生渲染器 |
| 工具调用 | 宿主原生工具视图（我们包框） |
| 帧的外壳（边框、圆角、一屏裁切、贴底） | 本包 |
| 帧的标题行（思考 + 图标、工具调用、回答 + 编辑/复制） | 本包，用宿主的 `DisclosureRow` 与官方图标 |

## 帧的结构

```
┌ 帧（一屏高，超出向上裁掉，输出贴底） ─────────────┐
│ 标题行（官方样式）                                │
│ 正文（宿主渲染）                                  │
└───────────────────────────────────────────────────┘
```

- 思考帧：官方 `DisclosureRow`（思考 + 官方图标），正文逐行增长；满屏后旧的内容
  被裁掉、继续往下写。
- 工具调用帧：标题「工具调用」，内容是宿主的原生工具视图。
- 回答帧：标题「回答」+ 右侧编辑/复制（回答完成后出现），正文是原生渲染。

## 与既有 DOM 层的关系

DOM 层（`src/turn-fold.ts`）只管**布局**：限高、裁切、贴底、历史轮折叠、请求条，
以及两处布局安排（过程组头让位给我们的帧、「已完成·用时」搬进回答栏）。
React 层负责**帧的内容与标题**。两层靠稳定的 data 标记对齐
（`data-chat-power-frame-box`、`data-chat-power-think-frame`、
`data-chat-power-tools-frame`、`data-chat-power-capped`）。
